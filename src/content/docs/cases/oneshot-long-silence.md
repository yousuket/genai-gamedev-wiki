## 概要

THE LONG SILENCE は、Anshu Chimala 氏が2026年7月にClaude Opus 5で作った、ブラウザで動く宇宙探索ゲームです。宇宙船を操縦し、星系を調べ、惑星に降り、船内を歩けます。
作者は「24時間ぶっ通しで走らせた」と述べ、「ワンショットではなく数段階で作った」とはっきり書いています。初回のプロンプトと、ビジュアルを磨く24時間の `/goal` プロンプトの両方が、Xの投稿で全文公開されています。
Claude of Duty の「実物と比べる批評役」を、宇宙ゲーム向けに取り入れた事例です。

## 何が作られたか

READMEによると、ゲームは次のような内容です（2026年9月時点）。

- 物語: 4万年前、80光年の範囲にある900の居住星が4日で沈黙した。プレイヤーは調査船 Pale Seeker を操り、星系を調べ、7つの「共鳴器」に同調してドライブを強化する。7つそろうと「開口部」が開く
- 遊び: 操縦、スキャン、ワープ、惑星への着陸、船内の歩行、星図、アーカイブ
- 規模: 世界の1単位が1km。数百万単位の星系の中で全長0.1単位の船を扱うため、原点を船に固定する「浮動原点」と対数深度バッファを使っている
- 惑星: 実行時に立方体マップへ焼き込む（1ピクセルごとに20オクターブ超のノイズを毎フレーム計算しない）。大気は単一散乱のレイマーチ
- 描画: 自動露出をGPU上で行い、ブルーム、レンズ効果、AgXトーンマップを自前で組んでいる。フレーム時間を見て描画解像度を0.62〜2倍に動かし、60fpsを保つ
- 交通: シミュレーションではなく、時計に合わせた解析的な軌道で動かす。ワープ後や一時停止後も正しい位置にいる

READMEは、スマートフォンでは動かさないと書いています。手持ちの端末では負荷に耐えられないため、簡易版ではなく「非対応」のメッセージを出します。

「アセットなし」の範囲は時期で変わっています。作者の7月のX投稿は「外部のアセットもコードもなし。すべてClaudeが作った」でした。現在のREADMEは、地面の素材（材質、石、葉）は画像生成モデルとBlenderで作り、画像と小さなGLBとして同梱していると書いています。写真や第三者のファイルは使っていない、という位置づけです。

## プロンプトの中身

プロンプトは2つあり、どちらも作者のX投稿の[返信](https://x.com/anshuc/status/2081801979131818412)に全文があります。全文は転載せず、構造を整理します。

### 1つ目: 初回のプロンプト（高い推論強度）

空のリポジトリに、Three.jsで宇宙探索ゲームを作らせるものです。

| 要素 | 内容 |
|---|---|
| 進め方 | 質問せず、ゲームの仕組みは自分で決める |
| 譲れない条件 | 見た目がAAAスタジオ品質で、写真のよう。低解像度・低ポリゴン・プラスチック風は不可 |
| 内容 | 宇宙船を操縦する。船内を歩いて操作できる。コックピットにも座れる |
| 品質 | グラフィック、ストーリー、音、メニュー、HUDまで細部を詰める |
| 制約 | 外部のアセットやコードを持ち込まない（three.jsのみ） |
| ゲームループ | 飛ぶ、発見する、学ぶ、目標に近づく、次の場所へ行く理由がある。チュートリアルの押しつけはしない。宇宙の広大さと退屈さのバランスを取る |
| 検証 | ブラウザで自分で確かめ、60fpsで最後まで動く。完成したと思ったらスクリーンショットを撮り、AAAや写真のように見えなければ画質を改善する |

ゲームの内容（物語、目標、仕組み）はモデルに任せています。譲れない条件は「見た目」の1点だけです。

### 2つ目: 24時間の `/goal` プロンプト（最高の推論強度）

初回の出力を土台に、ビジュアルを磨く長時間の目標を渡しています。

- 手続き生成のまま、見た目を限界まで上げる。並列のサブエージェントに作業を分ける
- 宇宙を「生きている」感じにする。他の船に会える、惑星に降りられる、カットシーンは途切れなく
- Blenderが使える。Blenderのスキルを読み、サブエージェントに高品質なモデルを作らせる（並列にできないので順番待ちにする）。「ブロック状で手続き生成だと分かる物は見たくない」
- z-fighting（面のちらつき）や帯状の縞などの不具合を、カットシーンとゲームプレイのフレームをシートにまとめて探し、直す
- 完了の条件: 独立した、公平な判定役のサブエージェントを置く。判定役は Starfield のようなAAA宇宙ゲームの画面と自作の画面を見比べ、具体的に批判する。判定役が「AAAと同等」と言うまで完了にしてはいけない。判定役のプロンプトを書き換えて条件を緩めてはいけない

作者は、この判定役を Matt Shumer 氏の Claude of Duty の考え方から取ったと書いています。また、判定役を書き換え禁止にする一文は、Claude of Duty のプロンプトにはない追加です。

## 進め方（エージェントの運用）

作者の説明では、進め方は次のとおりです（X投稿）。

1. 初回のプロンプトで最初の版を作らせる
2. Claude Codeに Blender MCP を入れさせる。「見つけてきて自分で入れた」という
3. Blenderで宇宙船を作らせ、良くなるまで感想を返す
4. 学んだことをすべてスキルにまとめさせる。これが `.claude/skills/blender-hardsurface` で、リポジトリに入っている
5. 24時間の `/goal` を走らせる

実行中の関わり方についても書かれています。Claudeはほぼ自律で動き、作者はスマートフォンから見守り、数回だけ方向を変えました。たとえば、宇宙や惑星に時間をかけすぎていたので、船内に集中させています。作業の大半は、作者が席を外している間や眠っている間に進みました。
また、`/goal` は完了しませんでした。判定役が批判し続け、一晩たっても走り続けたので、作者が手動で止めています。その後、別のClaudeに描画の不具合をいくつか直させ、録画、整理、デプロイを行いました。

リポジトリの `tools/` には、ゲームを検証する道具があります。`play.mjs` が操縦、スキャン、ワープなどを17項目のアサーションで確かめ、`survey.mjs` がすべての見せ場を撮影してフレーム時間と描画コール数を出します。`levels.mjs` はフレームの明るさの統計を出します。READMEは「『平板に見える』は議論を進められないが、『99パーセンタイルが165』は進められる」と、数値で見る理由を説明しています。

### 9月の更新

リポジトリの履歴は、7月27日の最初のコミット（初回コミットは全体をまとめた1つ）と、9月2〜3日の49コミット（マージを含む）に分かれます。9月の更新では、着陸後の地面の描画を頂点ごとの計算から配置パスに変えて、最悪フレームを50msから13msにしています。地面の素材は画像生成モデルとBlenderのスクリプトで作り、船体は Blender で削り出す方式に変わりました。旧版と新版を並べて比べる動画（コミットの名前は「montage」）を作る道具も追加されています。コミットには「Co-Authored-By: Claude Fable 5.1」と Claude のセッションへのリンクが付いています。

## 結果と限界

- 判定役は最後まで満足せず、目標は未完了で止められた（X投稿）
- 一晩の自律実行のあとに、別のClaudeが描画の不具合を手直ししている。1回の実行では、録画できる状態にならなかった（X投稿）
- 時間は「24時間」と公表されているが、費用、トークン数は公開されていない
- スマートフォンは非対応。Issue #3 では、Windows 11のEdgeでページが正しく表示されないという報告がある（2026年9月29日時点でオープンのまま）
- 遊びの面白さの評価は公開資料にない。READMEが説明するのは描画と検証が中心で、ゲームループ（7つの共鳴器を集める）が遊んで楽しいかどうかは書かれていない
- 9月時点のREADMEは「アセットなし」から「地面は画像モデルとBlenderで作った素材」に変わっており、7月の説明とは一致しない

## 学べること

### 自分で試すなら

1. 2段階に分ける。「最初の版を作る」と「見た目を磨く」を別のプロンプトにします。未完成の骨組みに対して判定役を回すと、判定役と作る側がぶつかり続けるためです（この理由は推測です）
2. 初回は「譲れない条件」を1つに絞る。この事例は見た目だけを絞り、仕組みは任せました
3. 判定役を置き、書き換え禁止にする。比較対象は実在のAAA作品です。詳しい型は [検証ループ](/agent-dev/verification-loop/) にあります
4. 長時間の実行は、`/goal` のように終わり方を条件で決める。終わらないときは人間が止めます。時間は24時間でした
5. 不具合探しをフレームのシートで行わせる。z-fightingや縞は、カットシーンとプレイのフレームを1枚にまとめると見つけやすくなります（[手続き生成アセット](/agent-dev/procedural-assets/)）
6. 外部ツールの手順をスキルにする。Blender MCPで学んだことをスキルとして保存し、次の実行で再利用しています（[プロジェクト指示ファイル](/agent-dev/project-instructions/)）
7. スマートフォンで見守る。作者は席を離れて、方向修正だけ行いました（[並列エージェント](/agent-dev/parallel-agents/)）

### ポン出しの先で独自性を出すなら

この事例は、ポン出しの後に自作の道具と手作業を足す例として使えます。全体像は [ポン出しの先へ](/agent-dev/from-one-shot-to-product/) と [独自性の出し方](/agent-dev/differentiation/) にあります。

- 手続き生成の限界を認め、別の手段を混ぜる。作者は「積み木のような組み立てには天井がある」という学びをスキルに残し、船体をBlenderで作り、地面の素材を画像モデルに任せました
- 世界観と物語を決める。この事例の物語（沈黙した900の星と7つの共鳴器）は、初回のプロンプトの「ストーリーまで詰める」という指示から、モデルが作ったと読み取れます。自分のゲームの独自性は、ここを人間が決めることで出せます
- 遊びを検証する。描画の評価は充実していますが、ゲームループの面白さの評価は空白です。プレイして、目標の設計を直す工程が残ります（[コアループ](/design/core-loop/)）
- 手触りを詰める。船体、コックピット、噴射炎など、見た目の要素は9月にも大きく更新されており、初回の出力が出発点にすぎないことが分かります
