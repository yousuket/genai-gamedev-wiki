## 概要

Starfall は、Mike Luan 氏が2026年7月にClaude Opus 5で作った、Homeworld 風の宇宙リアルタイムストラテジー（RTS。多数のユニットを指揮して戦う）です。Matt Shumer 氏の Claude of Duty のプロンプトを、ジャンルと基準のゲームだけ差し替えて使っています。
作者はX投稿で、トークン数と費用（約633ドル）を内訳つきで公開しました。ブラウザでプレイでき、ソースはMITライセンスで公開されています。
この記事では、プロンプトの差分、費用の中身、公開後数日の修正から、「1本のプロンプトの出力に何が足りないか」を読み取ります。

| ジャンル・規模 | 宇宙RTS。13種類の艦船、TypeScript製、Three.js、シミュレーションは固定60Hz |

## 何が作られたか

READMEの機能一覧は次のとおりです（2026年9月時点）。

- 偵察機から全長2kmの母艦まで、13種類の艦船クラス
- Homeworld 式の3次元移動。右ドラッグの上下で命令の高度を指定する
- 陣形、待機・攻撃などの姿勢、コントロールグループ、艦隊一覧バー、範囲選択
- 生産、研究、資源採取、敵AI
- ドライブの噴射炎、曲がる航跡、イオン砲、曳光弾、シールド、多段の爆発
- 戦闘の激しさに合わせて切り替わる音楽

描画の方針は「画像ファイルを1つも使わない」ことです。船体は断面形状を並べて滑らかにつなぐ「ロフト」で作り、板の段差や機械部品を、三角形の予算の範囲で足します。惑星はノイズ、背景の星雲は立方体マップに焼き込み、これを環境光にも使うので、艦船は背景の星雲に照らされます。
大艦隊を描くため、同じ形の船は `InstancedMesh`（同じ形を1回の描画でまとめて出す仕組み）で描き、遠くはビルボード（板ポリゴン）に置き換えます。

音声だけは外部素材です。音楽は OpenGameArt、効果音は Kenney の素材で、いずれもCC0（著作権放棄）です。X投稿の「Asset: none」の後、7月28日のコミットで音楽をCC0素材のストリーミングに差し替えています。理由はコミットメッセージに「2つのノコギリ波は音楽ではない」という趣旨で書かれています。

## プロンプトの中身

作者はプロンプトを [prompt.md](https://github.com/e01-ai/starfall/blob/main/prompt.md) とXの[投稿](https://x.com/mikeluan123/status/2081727054928900211)で公開しています。冒頭で「Matt Shumer 氏のAAAプロンプトを改変したもの」と明記しています。元のプロンプトとの差分は次のとおりです。

| 部分 | Claude of Duty | Starfall |
|---|---|---|
| 目標 | 最新のCall of Dutyに並ぶFPS | Homeworld 風の、宇宙規模のRTS。「規模の大きさ、巨大さの感覚」を足している |
| 比較の基準 | 実際のCall of Duty | 実際のHomeworld |
| 分担・批評役・`/loop`・`ultracode` | あり | ほぼ同じ文面 |
| 範囲の指定 | なし | 「ランダムモードだけでよく、ミッションは不要」 |
| 要求の追加 | なし | 艦船を複数種、UI・HUD・ゲームの仕組み、操作の滑らかさ、「最高品質」 |
| 描画の指示 | 「Three.jsで」のみ | 船と効果はシェーダー、生成テクスチャ、インスタンシングを使う |

差分から分かることが2つあります。1つ目は、範囲を絞る一文が入っていることです。「ミッション不要」と書いて、作る量を減らしています。2つ目は、RTS特有の負荷（数百隻を同時に描く）に対して、手段の名前（シェーダー、インスタンシング）を最後に書き足していることです。FPSのプロンプトにはなかった一文です。

## 進め方（エージェントの運用）

作者は「設計書も、アセット一覧も、アーキテクチャも、事前に指定していない」と書いています（README、prompt.md）。最初のコミットのメッセージによれば、構成は「契約先行」です。

- `core/types.ts` に共有する型を、`core/contracts.ts` にモジュールのインターフェースを置く
- `core/registry.ts` が13艦船の唯一の定義元（武装の位置、エンジンの位置、コスト、研究ツリー）
- シミュレーションは固定60Hzで、描画は状態を読むだけで書き換えない

これは Claude of Duty の ARCHITECTURE.md と同じ考え方で、エージェントが独立に作れるよう、先に共有の型を固めています。プロンプトにアーキテクチャの指定がないのに契約先行の構成になっているため、モデルが自分で契約を作ったと読み取れます（推測）。

### 費用

READMEは「最初の実行で約633ドル」と書いています。

| 種類 | トークン数 |
|---|---|
| 入力 | 6.86万 |
| 出力 | 460万 |
| キャッシュ読み取り | 8億3,720万 |
| キャッシュ書き込み | 1,360万 |

出力の料金は100万トークンあたり25ドルなので（[Anthropic](https://www.anthropic.com/news/claude-opus-5)、2026年9月時点）、出力だけで約115ドルです。残りの約518ドルは、入力側、つまり主にキャッシュの読み書きです。1回の実行で、累計8億トークン超をキャッシュから読み込んでいます。長い実行の中で、蓄積した文脈が繰り返し読み直されたことを示します。実行時間は公開されていません。
X上では、この数字に「そのトークン数で足りるのか」と疑問を投げたコメントがあったと解説記事は伝えています（explainx.ai。二次情報）。

## 結果と限界

作者は動画に「軽微なゲームプレイ上の問題はあるが」と添えています（X投稿）。公開後の数日間のコミットは、最初の出力に足りなかったものを示します。コミットメッセージに書かれた内容の要点です。

| 日付（UTC） | 見つかった問題 | 内容 |
|---|---|---|
| 7月26日 | 体感の調整 | 見た目の作り込みを2回、カメラの手触り、選択の精度、ミニマップの操作、生産パネルが「表示されるだけで何も起きない」状態だった |
| 7月26日 | 描画の重さ | ノイズのハッシュ関数を `sin` を使わない形に変更し、1440pで13fpsから61fpsになった |
| 7月27日 | 表示の破綻 | 空のブルームが画面全体に広がる、弾の軌跡が艦船の38倍の大きさ、噴射炎が自分の深度判定で消える、マウスドラッグでのパン操作がない |
| 7月27日 | 選択の操作 | 選択枠が小さくて見えない、全長2kmの船の船首から離れた場所をクリックしても選ばれる |
| 7月27日 | 縮尺 | 全船が同じ大きさの板で覆われ、母艦が「レンガの壁」に見えた。命令マーカーが8.4倍の大きさだった |
| 7月28日 | 描画の欠落 | 噴射炎が見えなかった原因は、シェーダーではなく、WebGLのフィードバックループ（描画先のテクスチャを同時に読む）で描画呼び出しが丸ごと捨てられていたこと |
| 7月28日 | 音 | 合成音だけの音楽を、CC0素材の音楽に置き換えた |

特に「噴射炎が見えない」問題は、1回目の修正（シェーダーの調整）では直らず、2回目でパイプラインの不具合と分かったと書かれています。見た目の批評だけでは原因にたどり着きにくい種類の不具合です。READMEによれば、`scripts/` に画面を撮る、実行中のシーンを検査する、画像のヒストグラムを読む、マウス操作がカメラに与えた効果を測る、の4種類の道具があり、修正のほとんどはこれで見つけたとのことです。
ゲームとしての評価（バランス、敵AIの強さ、対戦の面白さ）は公開資料にありません。Claude of Duty のような批評役のスコアも公開されていません。リポジトリの反響は、2026年9月29日時点で星69、フォーク23です。Claude of Duty（星約3,400）より小さい規模です。

二次情報の更新漏れが1点あります。explainx.ai は2026年7月28日の記事で「公開リポジトリは確認できていない」と書いていますが、リポジトリは同日に作られ、現在は公開されています（GitHubの作成日時: 2026年7月28日）。

## 学べること

### 自分で試すなら

1. 元のプロンプトを別ジャンルに移すなら、変えるのは目標と比較の基準（実在のゲーム）だけでよい、という実例です。分担・批評役・ループの部分はそのまま使えています
2. 範囲を絞る一文を入れる。「ミッションは不要」「ランダムモードのみ」のように、作らないものを書くと、作る量が減ります
3. ジャンル特有の負荷を、最後に一文で名指しする。RTSでは大量のユニット、つまりインスタンシングです（[ウェブゲームの技術構成](/agent-dev/web-game-stack/)）
4. 費用は約633ドルを一つの目安にする。Opus 5の入力・出力の単価より、長い実行で膨らむキャッシュ読み取りが費用の大半を占めます（[コスト管理](/agent-dev/cost-management/)）
5. 最初の実行の後に、数日の修正期間を見込む。操作、縮尺、描画の欠落は、実行後に人間が触って気づいた種類の問題です

### ポン出しの先で独自性を出すなら

「ミッションは不要」と書いた以上、ゲームとして足りないものが明確です。詳しくは [ポン出しの先へ](/agent-dev/from-one-shot-to-product/) にまとめています。

- 遊びの骨格を足す。勝利条件、ミッション、艦種ごとの役割（じゃんけん構造）、資源の駆け引きを決めます（[コアループ](/design/core-loop/)）
- 操作を作り込む。コミット履歴を見ると、修正の多くは操作と可読性でした。自分で遊んで違和感を1つずつ直す工程が、独自性の中心になります（[ゲームフィール](/agent-dev/game-feel/)）
- 素材の選択を人間が決める。音楽は合成をやめて既製のCC0素材にしています。作りたい雰囲気に合う素材を選ぶのは人間の仕事です（[手続き生成アセット](/agent-dev/procedural-assets/)）
- 元ネタとの距離を決める。Starfall は「Homeworld のアート、音声、コード、商標を一切使わない独立したオマージュ」と明記しています（[著作権](/legal/copyright/)）
