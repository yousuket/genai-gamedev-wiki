## 概要

「カピバラがスクーターで果物を配達する」Three.js 製のブラウザゲームです。作者はiOSエンジニア歴約9年で、ゲームを作るのはこれが初めてでした。
コードの90%以上をAIに書かせることが条件のゲームジャム Vibe Jam 2026 に、2週間で作って提出し、約1,000本の応募作の中から1位（賞金25,000ドル）に選ばれました。
コード、ロゴ、テクスチャ、3Dモデル、音楽、効果音のすべてをAIで作り、人間がやったのは「プロンプトを書く」「遊んで手触りを調整する」「足りない部分を見つけて、それを埋めるツールをAIに作らせる」ことだと作者は書いています。

## 何が作られたか

コアループは3つの部分でできています（作者の記事より）。

1. スマートフォンの画面で注文を受ける。注文ごとに難易度が違い、品数が多いほど荷崩れしやすい
2. コンビニに入り、制限時間内に注文の品を集める。床が滑り、壁で跳ね返される
3. スクーターの荷台に積んだ荷物を運ぶ。荷物は物理演算で傾き、ハンドル操作次第で崩れる

この周りに、街・郊外・田舎のエリア、コルコバードのキリスト像やハリウッドサインを模した名所、昼夜と雨、ドリフトのブースト、他プレイヤーと同じ街を走れるマルチプレイが載っています。
スマートフォンの画面はCSSだけで作られ、地図アプリ（CapyMaps）や、ゲーム内で実際に音楽が鳴る音楽アプリ（Capify）まで用意されています。最初のスマホUIは、一発で生成されたものがそのまま使える出来だったと作者は述べています。

## プロンプトの中身

プロンプトの全文は公開されていません。作者の記事に載っている断片と、使い方の方針から分かることをまとめます。

### 公開されている指示の例

- 地図エディタの依頼: 「Claude, create an editor tool with terrain construction and an entire road system…」（記事より）。地形の筆、道路の自動生成、街灯と歩道までを1回の依頼で頼んでいます
- 木の描画: 平面を2枚、90度回して「X」の形に置く、と形状まで具体的に指示（記事より）
- 調整用UIの依頼: 「もっと速く」「もっと大きく」とAIに頼む代わりに、すべてのオブジェクトの数値をスライダーで変えられ、設定ファイルに保存されるようにするルールを作る

### プロジェクトのルール

作者は、ジャムの規約と「モデルには自明でないが、このプロジェクトでは重要な」コーディング規約を、Claude Code の `.claude/rules` に入れて始めています。規約違反で失格になるのを避けるためです。ルールの書き方は [プロジェクト指示ファイル](/agent-dev/project-instructions/) も参照してください。

### 画像側のプロンプト

主人公は、GrokとGPTにスタイル違いの一覧シートを作らせ、絞り込んでから、正面・背面・側面の3方向の絵を出させています。3Dモデル化の入力に使うためで、角度が多いほどAIが「推測」せずに済むと作者は書いています。

## 進め方（エージェントの運用）

作者は、コードを書かせる時間より、考える・計画する・遊ぶ時間のほうが長かったと書いています。流れは次のとおりです。

- 進め方の基本: 「私が考え、Claudeが調べ、ブレストし、計画を立て、私が承認し、Claudeが生成し、私がテストする」
- plan モードで、機能ごとに計画書（.mdファイル）を作らせてから実装させる。セッションが切れても計画書を読み直せる
- 計画を立てる前に「あなたのほうから私にインタビューして」と頼む。作者の意図に沿った実装になりやすいとのこと
- 2〜3本の Claude Code セッションを同時に動かし、それぞれ別のコード領域を担当させる。新機能は必ず文脈のない新しいセッションで、バグ修正は文脈が要るので長く続けるセッションで行う（[並列エージェント](/agent-dev/parallel-agents/)を参照）
- `/loop`（自動反復）は使わなかった。手触りの良し悪しは自分で遊ばないと分からず、自動反復はトークンを無駄にして品質も落とすと判断した
- 足りないものが見えたら、その道具をAIに作らせる。マップエディタ、道路ビルダー、カットシーンのタイムラインエディタは、いずれもAIが書いたツールです

### 2週間の流れ

| 時期 | やったこと |
|---|---|
| 1週目 | 主人公の操作と当たり判定、荷物の物理、コンビニ、スマホUI、注文からの一連の流れ、天候、マップエディタ、マルチプレイ、仮の効果音 |
| 2週目 | PS1風の見た目への統一、生成した質感画像の貼り替え、道路ビルダーの強化、マップ作り込み、カットシーンエディタ、7言語対応、提出用サムネイル |

## 結果と限界

- 結果: Vibe Jam 2026 で1位。levelsio氏の発表では、審査員は今年のゲームは昨年よりずっと質が高いと評価しています
- AIにマップを丸ごと作らせる試みは失敗しました。Grokで描いた絵を Tripo3D で3D化しましたが、細部を指定できず、拡大すると崩れ、1枚もののため最適化もできませんでした。最終的にはエディタで手作りしています
- 3Dモデルの生成は一発で決まらず、橋のモデルは20回生成しても細部の問題が残ったと書かれています
- 作者が楽しいと言った箇所でも、審査員には不評のものがあります。コンビニは動きにくく、ジャム後も評価が低いままです
- Ctrl+Z を頼み忘れ、2週目まで取り消しのないエディタで作業していました
- 7言語対応は、作者が分かる言語ではClaudeの翻訳がよく、他の言語は別のエージェントで検証する予定と書かれています
- 作者はSteamでの販売はしないと述べています。遊べるのは5〜10分程度で、進行の実感や数時間分の内容が足りないためです

## 学べること

### 自分で試すなら

- 目安: Opus 4.7 クラスのコーディングエージェントと Three.js があれば、ゲーム制作未経験でも2週間で、遊べる3Dのゲームジャム作品まで到達できる例です。ただし作者は、この期間の多くをブレスト・計画・プレイテストに使っています
- コードは1つの道具に任せ、画像・3D・音楽は別の生成AIに分けています。素材ごとに専用ツールを選ぶ構成は、[プロシージャルなアセット](/agent-dev/procedural-assets/)の考え方とあわせて検討できます
- 費用について、作者はコスト表を載せており、二次情報の wccftech は、プランを5倍から20倍に上げた追加100ドルを報じています
- 始め方は、ジャムの規約や守ってほしい規約を先にルールとして置き、機能ごとに計画書を作らせて承認してから実装、の順です

### ポン出しの先で独自性を出すなら

作者が独自性の源泉として挙げたのは、次の点です。

- 遊びの手触りは人が決める。荷物の物理は、最初は現実的な挙動でしたが、「一定の傾きを超えたらX%の確率で落ちる」という、現実より面白さを優先した式に直して独自の遊びになりました。詳しくは [ゲームフィール](/agent-dev/game-feel/) を参照してください
- 世界を作り込む。マップは手作業で、遠くからも見える山の頂上にコンビニを置くなど、自分の構想で組み立てています。作者は、独自性の大きな部分は地図から来ていると書いています
- 小ネタを積む。カピバラ風にしたアプリ、スマホのロック画面、名所のパロディといった細部が、作品の個性になっています
- 制作用ツールを作らせる。作者は、最大の倍率になったのはゲームのコードそのものではなく、ゲームを作るための編集ツールをAIに作らせたことだったと総括しています

一発生成から製品に向けて進める手順の一般論は、[一発生成から製品まで](/agent-dev/from-one-shot-to-product/) と [独自性の出し方](/agent-dev/differentiation/) にまとめています。
