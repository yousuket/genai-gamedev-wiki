## 概要

fable51-worlds は、PhiloLabs が2026年9月2日に公開したリポジトリです。Claude Fable 5.1 のエージェント群が、実在の場所や映画の一場面を、Three.js だけで動く3Dの世界として作りました。収録は、サンフランシスコの Union Square、京都の東山、映画の一場面を元にした Death Star Trench Run の3つです。
Claude of Duty のような短い目標だけのプロンプトとは対照的に、Union Square のプロンプトは約1,590行の設計書です。同じ課題を GPT-6 Astra にも与えた比較動画も付いています。
ゲームに近いのは、操作して遊べる約3分のシネマティック、Trench Run です。この記事では、Trench Run を中心に、Union Square のプロンプトと費用の申告を合わせて読みます。

## 何が作られたか

### Death Star Trench Run

READMEによれば、映画『スター・ウォーズ』の一場面を元にした3分12秒のシネマティックで、途中の「トレンチラン」が操作できます（2026年9月時点）。

- 舞台の縮尺は1単位が1m。直径100kmの要塞、長さ30km・幅124m・深さ105mの溝が、大円に沿って曲がっている
- 12のフェーズと30のカメラショット。接近、編隊、敵機の迎撃、急降下、溝への進入、操作可能なラン、照準、魚雷、脱出、6段階の破壊、余韻
- 操作は WASD、`Q`/`E` でロール、`Shift` でブースト、`Space` でレーザー、`F` で魚雷、`C` で自動操縦。開始時に「Launch」（溝から操作）と「Cinematic」（全自動）を選ぶ
- テクスチャ、モデル、音声ファイルは使わず、すべてコードから生成する

「映画の一場面を元にする」使い方が珍しい点です。READMEによれば、入力は映像のクリップで、それから作られたブリーフ（作業指示書）が [PROMPT.md](https://github.com/PhiloLabs/fable51-worlds/blob/main/death-star-trench-run/PROMPT.md) に全文で載っています。映像からブリーフがどう作られたか（人間か、モデルか）は書かれていません。

### Union Square

サンフランシスコの Union Square 周辺（約800×720m）を歩ける3Dで再現したものです。QAレポートによると、規模は次のとおりです。

| 項目 | 数 |
|---|---|
| 地図データから読み込んだ建物 | 453棟（OpenStreetMap） |
| 識別された店舗 | 129（うち中に入れるのは Apple と Nintendo の2店） |
| 歩行者と車両 | 220人、109台 |
| 生成した3Dモデル（Blenderでオフラインで作成） | 206ファイル、5.1MB |
| 画面の比較テスト | 14回の実行で147シート |

実行時はThree.jsだけで、BlenderはPythonライブラリとして事前のアセット生成にだけ使っています。

## プロンプトの中身

### Union Square: 約1,590行の設計書

[PROMPT.md](https://github.com/PhiloLabs/fable51-worlds/blob/main/union-square-sf/PROMPT.md) は、Claude of Duty（約150語）とまったく違う形です。作者はHacker Newsで「ワンショットの結果だが、とても長いプロンプトで、サブエージェントの使い方と自己QAのループを明確に指示している」と説明しています。構成の要点は次のとおりです。

| 部分 | 内容 |
|---|---|
| 体験の定義 | 開いた瞬間にUnion Squareが見える。ここまでは実在の街と分かる |
| 品質の目標 | 「おもちゃではなく、数棟の代表的な建物でもない」 |
| 調査フェーズ | Google Earth、写真、公式ページを参照資料にして並列に調べる。ただし、Googleの3Dデータや画像は成果物に含めない |
| 並列の再構築 | 広場、西・東・北・南の各通り、店舗の一覧、Apple、Nintendo をそれぞれ担当するエージェント |
| アセット生成 | 建築、街の設備、小売、車両、植物ごとのエージェント |
| 内容の指定 | 建物の3段階（塊、外壁、路面レベル）、店舗、内装、歩行者、車、ケーブルカー、時刻、素材、看板 |
| 検証 | 幾何、意味（正しい店が正しい場所か）、視覚（建築家、地元民、テクニカルアーティスト、ゲーム環境アーティスト、操作）の各レビュー役。実写との重ね合わせ |
| 進め方 | マイルストーン0〜11。並列は「必須」。各サブエージェントに範囲、変更できるファイル、成果物、確認方法、最大トークン予算を与える |
| 終了条件 | 品質の点数の目標（地理9、建物の見分けやすさ9など）を満たすまで止めない。人間に質問しない |

Claude of Duty と比べると、プロンプト自体が設計書として作品の内容と検証の仕組みを細かく決めています。トークン予算をサブエージェントごとに設定させる指示は、費用管理の手段としても参考になります（[コスト管理](/agent-dev/cost-management/)）。

### Trench Run: 約10KBの指示書

[Trench Run のPROMPT.md](https://github.com/PhiloLabs/fable51-worlds/blob/main/death-star-trench-run/PROMPT.md) は、Three.js、WebGL、GLSL、TypeScriptの指定から始まり、全体の流れ（接近から破壊まで）を矢印で示します。続く17項目で、X-wing、Death Star、トレンチ、操縦、敵機、砲台、シェーダー効果、魚雷、6段階の破壊、カメラ、ポストプロセス、性能を指定します。担当を分けるエージェントは8種類（機体、要塞の形状、トレンチ、シェーダー、敵機、操縦、カメラ、統合・性能）で、「各エージェントは範囲を限ったファイルを所有する」と書かれています。品質確認は3回（形状と縮尺、ゲーム性と演出、効果と最終品質）で、最後は「全編を実行して目で確認するまで完了を主張しない」と締めています。
「破壊を球体が光って消えるだけにしない」のように、失敗しがちな作り方を名指しで禁止しているのが特徴です。

## 進め方（エージェントの運用）

READMEは工程を4段階で説明しています。

1. 調査: 並列の調査エージェントが地図、標高、交通、店舗を調べ、各データに出典と確度を付ける（Union Squareでは11の調査エージェントが、OpenStreetMapの建物453棟、標高1,317点、店舗122件などを作った）
2. アセット生成: スクリプトが外壁、街の設備、車両、植物などの部品を出力する
3. 実行: Three.jsのアプリが、JSONの仕様から地形、街路、建物、群衆、交通を組み立てる
4. 検証: Playwrightがアプリを動かし、決まった視点でスクリーンショットを撮り、同じ位置の写真と比較する。独立したレビュー役が報告を出し、次の修正に回る。「作る役は自分の成果を採点しない」

Trench Run では、[CONTRACTS.md](https://github.com/PhiloLabs/fable51-worlds/blob/main/death-star-trench-run/CONTRACTS.md) が並列の作業者の約束事です。縮尺、トレンチの座標変換の関数、共通部品（乱数、オブジェクトプール、GLSLの部品集）を先に固定し、手書きの三角関数を禁じています。Claude of Duty の ARCHITECTURE.md、Starfall の `core/contracts.ts` と同じ発想です。検証用に `window.__demo` で固定タイムステップの再生とカメラの固定ができ、撮影は毎回同じ画像になります。

| 対象 | 時間 | トークン | 費用 | 出典 |
|---|---|---|---|---|
| Union Square | 約2時間（サブエージェントを大量に使用） | 約800万 | 約33ドル（API） | 作者のHacker Newsのコメント |
| Trench Run | 公開されていない | 公開されていない | 公開されていない | — |

Union Square の数字は作者の申告で、リポジトリの記録にはありません。Fable 5.1 の料金は入力100万トークンあたり10ドル、出力50ドルで、キャッシュの読み取りは0.25ドルです（[Anthropic](https://www.anthropic.com/claude/fable)、2026年9月時点）。

## 結果と限界

### 自己評価と残った問題

Union Square のQAレポートは、独立したレビュー役の2回目の採点を、目標に合わせて調整せずに載せています。

| 項目 | 点数（10点満点） | 目標 |
|---|---|---|
| 地理の正確さ | 7.5 | 9 |
| 建物の見分けやすさ | 5.5（修正後の推定6.5） | 9 |
| 店舗の正確さ | 6 | 9 |
| 街路の細部 | 6 | 8.5 |
| 素材 | 6 | 8.5 |
| 操作性 | 7 | 8.5 |
| 性能 | 6 | 8.5 |

すべての項目で、プロンプトの目標に届いていません。店舗では、識別できなかった住所が30件以上、リストに残っています。

Trench Run の主な不具合は、READMEの「視覚QAが見つけた欠陥」に書かれています。

- すべてのPBR素材が真っ白に発光していた。Three.jsの仕様（emissive の初期値）を2つのモジュールが取り違えていたため、シーン全体が白飛びした
- 空中戦が成立しなかった。自機が敵より4倍以上速く、敵は20km後ろで交戦しなかった
- カメラの追従の遅れ。速い対象に遅れて付いていくため、僚機が画面に入らなかった
- 要塞に穴が空いていた（トレンチをくりぬいたが、遠くからは貫通して見えた）
- 魚雷の前に自機が排気口を通り過ぎた

残った問題として、破壊のピークで画面が白に近づくこと、衝撃波が想定の速さで広がらず、カメラを横切る時間が0.5秒未満で撮影できないことが挙げられています。

### 性能

Apple M5 Pro のヘッドレスChromeでの実測です（README）。

| フェーズ | fps | 三角形数 |
|---|---|---|
| 接近 | 81 | 約55万 |
| トレンチラン | 98〜110 | 約190〜200万 |
| 破壊のピーク | 41 | 約20万（画面全体を覆う加算描画のため、描画解像度を自動で下げている） |

### モデル比較と第三者の反応

READMEには、同じブリーフを GPT-6 Astra に与えた結果との並列動画があります。「同じ条件で行い、Astra側の世界はFable側の動画を見る前に確定した」と書かれていますが、比較したのは作者側で、点数などの評価は付いていません。Astra側では4つのメッシュをBlender MCPで作ったと明記されています。

Hacker News（2026年9月2日、327ポイント）では次の反応がありました。

- 「World Modeling」という題名が紛らわしい、という批判が複数
- 建物のトポロジーやテクスチャの品質を疑う声。作者は、コードで作る世界はトポロジーが構造上きれいだが、テクスチャは課題と返答
- 重ね合わせ画像が合っていない、という指摘
- 「Opus 5でも同じことができて安い」「細部の精度が上がるとOpus 5では届かない」という、相反する個人の意見
- 1つのワールドが33ドルでは、ゲームにはまだ使えない、という意見

ゲームとしては、Trench Run のREADMEに勝敗、スコア、失敗条件の記述がなく、「遊べるシネマティック」という位置づけです。

## 学べること

### 自分で試すなら

1. 目標だけの短いプロンプトと、設計書型の長いプロンプトの2つの型がある、と知っておく。Claude of Duty は約150語で、作る内容をモデルに任せました。Union Square は約1,590行で、調査、担当分け、検証、終了条件まで書きました。指示の詳細さを選ぶ基準は [プロンプトパターン](/agent-dev/prompt-patterns/) に整理しています
2. 「失敗しがちな作り方」を名指しで禁止する。破壊を球体の消滅にしない、のような書き方です
3. サブエージェントごとに、範囲、変更できるファイル、成果物、確認方法、最大トークン予算を決める
4. 作る役と評価する役を分ける。評価役の点数を目標に合わせて調整せず、そのまま残す運用は、次の作業の入り口になります（[検証ループ](/agent-dev/verification-loop/)）
5. 固定タイムステップで再生でき、撮影が毎回同じになる仕組みを、最初に作らせる
6. 費用の目安は、街1つが約2時間・約800万トークン・約33ドル（作者の申告）です

### ポン出しの先で独自性を出すなら

- 遊びを足す。この事例の弱点は、ゲームとしての設計がないことです。READMEは「世界は土台で、その上に立つものが目的」と書いており、次の段階を作者自身がロードマップに置いています。自分で作るなら、この土台の上にコアループを決めて載せます（[コアループ](/design/core-loop/)、[ポン出しの先へ](/agent-dev/from-one-shot-to-product/)）
- 題材を自分の場所や好みに合わせる。実在の場所、映像、写真から作れるというのは、入力を変えるだけで世界が変わる、ということです。地元の街や、自分の映像を入力にすれば、他の人の作品と重なりにくくなります（[独自性の出し方](/agent-dev/differentiation/)）
- 品質の目標を数字にして、達成度を残す。点数を残すと、次に手を入れる場所が分かります
- 参照資料の扱いを決める。この事例は、地図データのライセンス（OpenStreetMapはODbL）、写真を再配布しない、映画の映像や音声は使わない、と分けて書いています（[著作権](/legal/copyright/)）
