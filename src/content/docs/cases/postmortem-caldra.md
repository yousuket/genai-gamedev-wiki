## 概要

Caldra は、個人開発者の DS_Seido 氏（Steam の開発元名は Dolphin Star）が作った、2人対戦のオンラインカードゲームです。「非ゲーム系エンジニア」を名乗る本人が、Unity のクライアントと、Rust で書いたロビーサーバー・ゲームサーバーを組み合わせ、AWS 上に運用しています。
2024年8月10日に着手し、2026年5月29日に Steam で早期アクセスとして無料公開しました。約1年10か月かかっています。
AIには Codex と Cursor を使い、特に慣れない Rust のサーバー側のコードを書かせました。開発者は、AIがなければまだ公開できていないと書く一方で、レビューが欠かせないこと、自分に読めないコードが生まれたことも、率直に記録しています。

## 何が作られたか

Steam のストアページによると、Caldra は、対戦中にコインでカードを売り買いしてデッキを強化する、競い合うデッキ構築カードゲームです（2026年9月時点）。

- カードを出すコストはなく、手札の使い方、買うカード、勝負に出るタイミングで戦略が決まる
- 3本勝負で、資源の管理と読み合いが勝敗を分ける
- 日本語・英語をはじめ9言語に対応

構成は、Unity のクライアント、Rust のゲームサーバー（ターンの進行、カード効果、勝敗判定）、Rust のロビーサーバー（ログイン、マッチング、プレイヤー情報）です。ログインには Steam のセッションチケットを使い、サーバー側でSteamユーザーを認証しています。カードのルールはすべてサーバー側で処理します。AWS 上のサーバーは2台あり、新しい版を片方に置いて確認してから、ロードバランサの向き先を切り替えます（Blue-Green Deployment に近い運用）。
カードのイラストは、BOOTH（クリエイター向けのオンラインショップ）などで購入した素材です。AI生成ではありません。

## 進め方（どうポン出しから製品にしたか）

この事例は、ポン出しから始まったわけではありません。本人の記録から、順序を整理します。

| 時期 | 作業 |
|---|---|
| 2024年8月〜9月 | 着手。ゲームサーバーのコアを、テストを書きながら実装（ターン進行、状態管理、カード使用、勝敗判定） |
| 2024年10月 | ひたすらカードの効果とテストケースを書く。着手3か月で、実装済みカード30枚がテスト30個に対応 |
| 2024年10月26日〜 | Unity のクライアントを実装。サーバーとつないで、受け取った状態を描画できるか検証 |
| 2025年3月 | このペースなら2026年1月に公開できると見積もった。実際は画面とアウトゲームの工数が想定より大きく、本業も忙しくなり、計画は崩れた |
| 2025年8月 | ロビーサーバー。ログイン、セッション、マッチング |
| 2025年9月13日 | Unity のクライアント同士で対戦できるようになる |
| 2026年2月 | 東京ゲームダンジョン（個人・インディー開発者の展示イベント）に申し込み、締め切りができたことで進みが上がった。Steam のストアページ作成（約2週間）と AWS の本番環境の構築（1〜2か月）を並行 |
| 2026年5月3日 | 東京ゲームダンジョンに出展 |
| 2026年5月29日 | Steam で公開 |

### AIへの指示の書き方

開発者は、指示を次の形で書いていると紹介しています。

```text
[作りたいもの]についてのコードを書いてください
・[狙い]をしたいです
・[仕様1]にしてください
・[仕様2]にしてください
・[制約]には気を付けてください
・[類似プログラム]を参考に作成してください
```

「狙い」には、その処理を足す理由を書きます。実際の指示の例として、「戦場のユニットがあふれるかもしれないことに注意する」「プログラムを書くときは xxx.rs を参考にする」といった書き方が挙げられています。
既存の類似プログラムを指定すると、設計や命名規則に寄せて実装するため、精度がかなり上がると述べています。

## 独自性をどこで出したか

- **試合の中でカードを売り買いする仕組み。** ストアページの紹介の中心は、「カードを出すコストはない」「コインで売買して、その場でデッキを組み替える」という点です。
- **ゲームの一番の肝であるサーバーを、AIとテストで固めた。** 勝敗のルールをすべてサーバーに置き、カードの効果を1枚ずつテストケースつきで実装しています。
- **人が対面で遊ぶ場を作った。** 東京ゲームダンジョンで直接遊んでもらい、カードゲーム好きから好意的な反応をもらえたことが、公開への自信につながったと述べています。
- **AIはコード生成が中心で、絵と音は購入した素材。** カードのイラストは約13,000円、ゲームのエフェクトは約9,500円、効果音は約3,000円の購入です。

## うまくいかなかったこと

- **AIが余計な気を利かせる。** 指示が足りないと、動くが読みにくいコードを書いたり、不要な機能を足したりします。本人は、指示に仕様と制約をできるだけ書き、Git の差分を必ずレビューする運用にしています。AIを使う前にコミットしておくと、差分で変更箇所が一目で分かります。
- **自分が読めないコードが生まれた。** 慣れない設計のロビーサーバーを、勉強のつもりでAIに書かせた結果、本人に読めなくなりました。本番では動いているものの、なぜ動くのか分からないと述べています。仕組みを人が理解できる範囲に保つ大切さは、[検証ループ](/agent-dev/verification-loop/) にも通じます。
- **スケジュールの見積もりが甘かった。** 着手から約7か月後には「2026年1月に公開できる」と見ていたものの、実際は約1年10か月かかりました。本人は「あなたが思う想定の1.5倍は掛かるはず」と書いています。
- **公開直後のバグ。** 公開後に、チュートリアルが進められないバグと、カードの効果が発動しないバグが報告されました。公開当日は、サーバーのエラーを見ながら食事をするだけのつもりだったと述べています。
- **サーバー費用が想定より高かった。** 下の表のとおり、月に約127ドルかかっています。開発者自身も、まとめて見て意外と高いと述べ、削減する必要があるとしています。

### 費用（開発者の集計。1ドル160円換算）

| 種別 | 内容 | 金額 |
|---|---|---|
| 開発時の買い切り | カードのイラスト、UI素材、Unity Asset Store のエフェクトと効果音、Steamへの出店料（100ドル） | 約42,800円 |
| イベント出展 | チラシ、小物、中古ノートPC、運搬費 | 約25,080円 |
| 毎月かかる費用 | AWS（約127ドル）とChatGPT（22ドル） | 約23,800円／月 |

AWS の内訳は、VPCエンドポイントが約43ドル、ロードバランサが約18ドル、管理用の EC2 が約21ドル、ゲーム用の EC2 が約14ドルなどです。

## 結果

- 2026年5月29日にSteamで公開しました。無料のため、本人も「プレイヤーがどれだけ増えても自分にお金が入る経路はない」と述べています。
- 公開後は0.0.2から0.0.5まで更新しています。制限時間の延長（75秒から90秒）、チュートリアルの不具合修正、初めてのバランス調整（強すぎるカードを弱め、弱いカードを強化）、対戦履歴の表示を入れました。
- 2026年6月24日の更新では、制限時間の方式を「ターンごとの制限」と「持ち時間制」の2つにして、試合ごとにランダムで使い分ける実験を始めました。どちらが好まれるかを、プレイヤーの感想で決める方針です。
- Steam のレビューは16件（好評11件、不評5件）で、評価は「賛否両論（Mixed）」です（2026年9月29日時点）。プレイ人数や起動数は公表されていません。

## 学べること

- **AIに任せる範囲を、慣れない領域に置く。** 本人は、Rust のサーバーやAWSといった初めての技術で、AIの効果を大きく感じています。作業によって開発時間が1/2〜1/10になったと述べ、サーバー側は想定の半分の期間で済んだとしています。
- **既存の実装を「参考にして」と指定する。** カード60種のように似た実装が並ぶ作業では、手本のファイルを指定すると、設計や命名が揃って精度が上がると本人は述べています。
- **指示は「狙い、仕様、制約、参考ファイル」で書く。** [プロンプトのパターン](/agent-dev/prompt-patterns/) と同じ考え方です。指示を絞るほど、余計な機能が減ります。
- **AIの前にコミットして、差分でレビューする。** 本人がもっとも強く勧める運用です。
- **読めないコードは、動いていても負債になる。** 個人開発なら許せても、業務では避けるべきだと本人も書いています。
- **締め切りは、外から作ると効く。** 展示イベントへの申し込みで、ストアページとサーバーの構築を一気に進められました。
- **無料公開でも、運用費は毎月かかる。** サーバー付きのオンラインゲームは、月々の固定費が発生します。費用の見積もりは [コスト管理](/agent-dev/cost-management/) も参照してください。
