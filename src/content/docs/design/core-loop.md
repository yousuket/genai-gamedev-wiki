## 概要

- **コアループ**とは、プレイヤーがゲーム中に何度も繰り返す行動のまとまり（例: 戦う → 報酬を得る → 強くなる → また戦う）です。
- その外側で、数時間〜数十時間かけて進む目標を**メタループ**と呼びます。
- この記事では、ループの考え方、具体的なジャンル例、そして「そのループが本当に面白いか」を小さなプロトタイプで確かめる手順を説明します。
- 個人開発では、コアループが固まる前に機能やコンテンツを作り込むと、作り直しで時間を失いがちです。最初に検証すべき対象として押さえておきましょう。

## ループとは何か

ゲームデザイナーの Daniel Cook は、ゲームの「遊び」の部分は繰り返される**ループ**でできていると説明しています（[Loops and Arcs](https://lostgarden.com/2012/04/30/loops-and-arcs/)）。1回のループはおおむね次の流れです。

1. プレイヤーが頭の中に「こうすればこうなるはず」というモデルを持つ
2. 行動する（入力する）
3. ゲームのルールが処理する
4. 結果がフィードバックとして返る
5. プレイヤーのモデルが更新され、次の行動につながる

Cook は、ループが短いものから長いものまで入れ子になっていること、そして繰り返し回すことで価値が生まれることを強調しています。一方、ストーリーのように一度通ったら終わる要素は**アーク**（arc）と呼び、ループと区別しています。自分の企画を見るときは「何が繰り返され、何が繰り返されないか」を書き出すと整理しやすくなります。

## コアループとメタループ

| 層 | 時間の長さの目安 | 役割 | 例 |
|---|---|---|---|
| 瞬間的な操作 | 数秒 | 触って気持ちいいか | ジャンプ、攻撃、カードを出す |
| コアループ | 数十秒〜数分 | 繰り返しても飽きないか | 1回の戦闘、1ステージ、1ターン |
| メタループ | 数十分〜数十時間 | 続ける理由があるか | アンロック、拠点強化、ストーリー進行 |

用語の境界は人や会社によって多少違います。大事なのは、**内側のループが単体で面白いこと**と、**外側のループが内側のループを変化させること**の2点です。メタループで手に入るもの（新しい武器、新しいカード）が、次のコアループの遊び方を変えるとき、2つのループがうまく噛み合っています。

Cook も、アーク（ストーリーなど）を取り除いてもループだけで遊びが成立するかを確認するよう勧めています（[Loops and Arcs](https://lostgarden.com/2012/04/30/loops-and-arcs/)）。

## ジャンル別の具体例

| ジャンル | コアループ | メタループ |
|---|---|---|
| サバイバー系（大量の敵を自動攻撃で倒す） | 移動して敵を避ける → 経験値を拾う → レベルアップで強化を1つ選ぶ | 1プレイの報酬で永続強化やキャラクターを解放する |
| ローグライク・デッキ構築 | 戦闘でカードを使う → 報酬のカードを選んでデッキを育てる → 次の部屋へ | 新キャラクター、難易度段階の解放 |
| 農場・生活シム | 作物を植える → 世話する → 収穫して売る | 資金で設備や土地を増やし、できることを広げる |
| パズル | 盤面を見る → 手を試す → 結果を見て考え直す | ステージを順に解放する |

ジャンルごとの向き不向きは [生成AIと相性の良いジャンル](/genres/ai-friendly/) も参照してください。

## コアループを書き出す

企画の最初に、次の3点を1枚にまとめます。

1. **プレイヤーが繰り返す動詞**: 「避ける」「選ぶ」「組み合わせる」など、3つ程度に絞る
2. **1周の流れ**: 動詞を矢印でつなぎ、最後が最初に戻る図にする
3. **1周ごとに何が変わるか**: 同じことの繰り返しにならない理由（ランダム性、選択、成長）

Game Developer の記事でも、コアループが定まらないまま開発を続けると、捨てることになる作業が増えると指摘されています（[Why the Core Gameplay Loop is Critical For Game Design](https://www.gamedeveloper.com/business/why-the-core-gameplay-loop-is-critical-for-game-design)）。スコープの決め方は [スコープの決め方](/getting-started/scope/) を参照してください。

## プロトタイプで検証する

カーネギーメロン大学の Experimental Gameplay Project は、1人1週間未満で50本以上のゲームを作った経験から、プロトタイプ作りのコツをまとめています（[How to Prototype a Game in Under 7 Days](https://www.gamedeveloper.com/game-platforms/how-to-prototype-a-game-in-under-7-days)）。コアループの検証に役立つ点を抜き出します。

- **まず「おもちゃ」を作る**: 勝ち負けや目標を入れる前に、中心となる仕組みだけを触れる状態にする
- **ごまかしてよい**: 見た目や正しい実装より、遊びを確かめることを優先する
- **だめなアイデアは早く捨てる**: うまくいかない案を延命しない
- **期間を区切る**: 時間をかけても得られるものは減っていく

### 検証の手順（例）

1. **1〜3日で作る**: 四角や丸の仮素材で、コアループ1周だけを動かす
2. **自分で10周遊ぶ**: 5周目以降も「もう1回」と思えるかを見る
3. **他人に遊んでもらう**: 説明せずに渡し、黙って観察する（[プレイテスト](/design/playtesting/)）
4. **判断する**: 次のどれかを選ぶ
   - 続ける: 仮素材でも繰り返し遊ばれた
   - 変える: 部分的に面白い。動詞を1つ足す・減らすなどして再検証
   - 捨てる: 何を変えても面白くならない

:::tip
「絵や音が付けば面白くなるはず」と考えたくなりますが、前述の記事は、見た目は壊れたゲームプレイを救えないと述べています。仮素材の段階で面白さの芽があるかを確認しましょう。
:::

## AIの活用ポイント

- **プロトタイプの高速化**: コアループ1周分のコードは、AIコーディングツールに任せやすい規模です。「Godotで、四角いプレイヤーが敵を避けて経験値を拾う最小プロトタイプ」のように、範囲を狭く指定すると成功しやすくなります。進め方は [AI駆動の開発ワークフロー](/dev-env/ai-workflow/) を参照してください。
- **使い捨て前提で作る**: AIで作ったプロトタイプのコードは本番に流用せず、検証が終わったら捨てる前提にすると、設計の粗さを気にせず速く回せます。
- **ループ図の壁打ち**: 書き出したコアループをLLMに渡し、「10周目に飽きる原因になりそうな点」を挙げさせると、見落としの確認に使えます（[AIを企画の壁打ちに使う](/design/ai-brainstorming/)）。
