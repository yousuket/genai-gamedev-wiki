## Overview

Caldra is a two-player online card game created by individual developer DS_Seido (Dolphin Star on Steam). The developer, who calls themselves a "non-game engineer," combined a Unity client with lobby and game servers written in Rust, running on AWS. Development began on August 10, 2024, and the game launched on Steam as early access (free-to-play) on May 29, 2026—taking approximately 1 year and 10 months. The developer used Codex and Cursor for AI assistance, relying heavily on AI to write the Rust server code, an unfamiliar language. In their account, they note that without AI, the game would not yet be released. However, they also candidly record that code review was essential and that some code generated by AI became unreadable to them.

## What was built

According to Steam's store page, Caldra is a competitive deck-building card game where players buy and sell cards with coins during matches to strengthen their decks (as of September 2026).

- Card play has no cost; strategy is determined by card choices, which cards to buy, and timing of plays
- Best-of-three format; resource management and reading opponents decide the outcome
- Supports 9 languages, including Japanese and English

The structure consists of a Unity client, a Rust game server (turn progression, card effects, win/loss determination), and a Rust lobby server (login, matchmaking, player information). Login uses Steam session tickets, with the server authenticating Steam users. All card rules are processed server-side. Two servers run on AWS; new versions are deployed to one server for verification before switching the load balancer (similar to Blue-Green Deployment).

Card artwork was purchased from marketplaces like BOOTH (a creator marketplace). It is not AI-generated.

This case did not start with one-shot generation. Based on the developer's records, here is the timeline:

### How to instruct AI

The developer describes writing instructions in the following format:

```text
Please write code for [what to build]
・I want to [aim/purpose]
・Please make [specification 1]
・Please make [specification 2]
・Please be careful about [constraint]
・Please refer to [similar program] when creating
```

The "aim" section explains why the process is needed. Examples cited include "be careful that units on the battlefield might overflow" and "when writing the program, refer to xxx.rs." When existing similar code is specified as a reference, design and naming conventions align, significantly improving accuracy.

## Key differentiators

- **The mechanic of buying and selling cards during matches.** The store page highlights that card play has no cost and that players rebuild their decks on the fly by trading coins. This is the core innovation.
- **Solidified the game's most critical part—the server—with AI and testing.** All win/loss rules are server-side; each of 60 cards was implemented with a corresponding test case.
- **Created a space for people to play in person.** Playing directly at Tokyo Game Dungeon with card game fans gave positive feedback, building confidence for launch.
- **AI primarily handles code generation; art and sound are purchased assets.** Card artwork: approximately 13,000 yen; game effects: approximately 9,500 yen; sound effects: approximately 3,000 yen.

## What did not go as planned

- **AI over-helps.** With incomplete instructions, it writes code that works but is hard to read or adds unnecessary features. The developer mitigates this by including as much specification and constraint detail as possible, and always reviewing Git diffs. Committing before using AI makes changed sections visible at a glance.
- **Code became unreadable to the developer.** Attempting to learn by having AI write the unfamiliar lobby server architecture, the developer ended up with code they could not read. It works in production, but they do not understand why. Understanding systems as a human remains crucial, as discussed in the [verification loop](/en/agent-dev/verification-loop/).
- **Schedule estimation was optimistic.** About 7 months in, the developer thought "launch by January 2026," but it took about 1 year and 10 months. The developer notes, "what you think will take should be multiplied by 1.5."
- **Post-launch bugs.** After release, two bugs were reported: the tutorial could not progress, and some card effects did not trigger. The developer had planned to just watch server errors during dinner on launch day.
- **Server costs ran higher than expected.** As shown in the table below, monthly costs are approximately $127. The developer themselves noted, reviewing the total, that it was unexpectedly high and needs reduction.

## Results

- Launched on Steam on May 29, 2026. Free-to-play; the developer notes, "there is no path for money to reach me no matter how many players join."
- Post-launch updates from 0.0.2 to 0.0.5 have included time limit extension (75 to 90 seconds), tutorial bug fixes, the first balancing pass (weakening overpowered cards, strengthening weak ones), and match history display.
- On June 24, 2026, the update introduced two time limit modes—"per-turn limit" and "total time bank"—used randomly per match. Which is preferred will be decided by player feedback.
- Steam reviews: 16 total (11 positive, 5 negative), rated "Mixed" (as of September 29, 2026). Player count and launch numbers are not disclosed.

## Key takeaways

- **Let AI handle unfamiliar territory.** The developer felt the biggest impact from AI on Rust servers and AWS—new technologies. Development time dropped to 1/2 to 1/10 for some tasks; the server side finished in half the expected time.
- **Specify existing implementations as references.** When similar implementations repeat (60 cards), specifying a reference file aligns design and naming, raising accuracy.
- **Write instructions with "aim, specification, constraint, reference file."** This mirrors the approach in [prompt patterns](/en/agent-dev/prompt-patterns/). Tighter instructions produce fewer unnecessary features.
- **Commit before AI, review via diff.** The developer most strongly recommends this workflow.
- **Unreadable code is a liability even if it works.** Acceptable in solo projects, but to be avoided in team or professional settings, the developer notes.
- **External deadlines drive progress.** Committing to the Tokyo Game Dungeon exhibition accelerated work on the store page and server setup.
- **Free games still have monthly operating costs.** Online games with servers incur fixed monthly expenses. See [cost management](/en/agent-dev/cost-management/) for further discussion.
